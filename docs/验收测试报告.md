## 3. 关键实现点

- **门禁是纯函数**：7 类检查（HOCON 结构、主键、映射、类型族、敏感未脱敏、预算缺失、cron），不依赖模型与数据面，同一输入永远同一结论。
- **风险评级与评测共用同一函数**（`harness.service.risk_of`），避免「线上 PDP 与 Benchmark 两套口径」这种典型漂移。
- **指纹三处校验**：版本 SHA256 → Preparation 快照 SHA256 → Commit 前重校验制品指纹，任一不一致即 `HARNESS_FINGERPRINT_CHANGED`。
- **Capability 单次消费**：`harness_capability_consumption` 上唯一约束兜底重放，不依赖应用层判断。
- **证据链**：`prev_hash + record_hash + Ed25519`，校验时同时验哈希与签名，任一条被改动都会暴露。
- **数据面真实**：执行器读源表、按质量规则分流、写影子表与错误表、改名 Swap，指标为实测值。

## 4. 实现边界（必须如实告知的部分）

| 条目 | 边界 | 影响 |
| --- | --- | --- |
| AC-02 | 仅 SQLite 参与真实测试与探查；MySQL/Doris/Oracle/ClickHouse 返回 `UNSUPPORTED` | 异构接入的编排与脱敏逻辑已具备，缺驱动与实例 |
| AC-03 | 规则化生成器，未接 LLM Provider；状态机自研，非 LangGraph 运行时 | 中断/恢复/Checkpoint 语义一致，生成质量不取决于模型 |
| AC-06 | 本地进程内执行，未接 Celery Worker 与 SeaTunnel Zeta | 调度语义（Outbox→消费→执行）具备，无分布式 Worker |
| AC-07 | SQLite 表改名等价 Swap，未接 Doris `REPLACE TABLE ... swap=true` | 原子性语义一致，方言不同 |
| 全部 | Secret 只登记 Vault 路径与版本，未接真实 Vault | 轮转记录可查，密钥未真正托管 |
| 全部 | 验证在 SQLite 完成，未在 PostgreSQL 上跑 | `timestamptz`、并发隔离、`FOR UPDATE` 未验 |

## 5. 本轮修复的缺陷

| # | 缺陷 | 后果 | 修法 |
| --- | --- | --- | --- |
| D-10 | 主键解析正则把 `upsert` 当主键 | 门禁正确拦住，但生成物不可用 | 只接受「主键是 X」「按 X 主键」两种句式，并排除保留词 |
| D-11 | 多次澄清时 Checkpoint 覆盖前序状态 | 回答第二个问题后丢失第一个答案，会无限追问 | 澄清快照改为 `{**params, missing}` 合并 |
| D-12 | Commit 时 `exec_run.id` 尚未 flush | Outbox 载荷写入 `"None"`，NOT NULL 失败 | 插入后先 flush 再组装 Outbox |
| D-13 | 一行命中多条规则被计多次 | 拒绝率虚高（12.5% 被算成 33%） | 每行只写一条错误记录，多命中只进 ErrorCode 分布 |
| D-14 | `studio_session.flow_run_id` 与 `flow_run.session_id` 循环外键 | 建表/删表排序告警，SQLite 不支持 ALTER | 去掉冗余外键，保留 `flow_run.session_id` 单向外键 |
| D-01…D-09 | 见上一轮报告（DB 惰性化、UUID 方言、时区比较、幂等后端、职责分离、种子脚本、前端类型、代理配置） | — | 已修复并回归 |

## 7. 尚未覆盖的风险

1. **未在 PostgreSQL 上回归**：本轮仍是 SQLite。唯一约束与部分索引已覆盖，但并发、时序精度、事务隔离没验。
2. **未做真实浏览器交互回归**：前端做到类型检查、构建通过、接口经代理走通，但没有点过每个按钮。
3. **Celery / SeaTunnel 缺席**：执行是同步本地调用，长任务、重试、Worker 崩溃恢复这些 Celery 才有的语义无法验证。
4. **LLM 生成质量无法评估**：规则化生成器保证确定性，但真实需求的泛化能力要接 Provider 后才能测。
