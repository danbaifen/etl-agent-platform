# 各模块 SPEC 总览

本目录按模块划分，每个模块一套文档。SPEC 的章节结构与深度参照 `gmall-spec-skill`，技术栈替换为本项目的 FastAPI + Vue 3。

## 1. 目录与命名

```
5_各个模块的文档/
  <序号>_<模块名>/
    后端SPEC.md
    前端SPEC.md
    后端开发部署手册.md
    数据对象设计.md      # 仅当实体超过 5 张、或存在不可变边界时提供
```

序号与概要设计 §4 的 M01–M12 一一对应，不补零（与参考项目 `1_分类管理`、`10_购物车` 一致）。

## 3. 章节模板

## 4. 与 gmall 模板的差异（有意为之）

| 维度 | gmall 模板 | 本项目 | 原因 |
| --- | --- | --- | --- |
| 表结构 | MySQL、`id` + 5 个通用字段、逻辑删除 | PostgreSQL、`uuid` 主键、`timestamptz`、按实体可变性决定是否可删 | 《数据实体设计》已冻结类型体系；协议与证据表禁止删除 |
| 后端分层 | Entity/Controller/Service/Mapper | Schema/Router/Service/Repository | FastAPI + SQLAlchemy 2.0 async |
| 接口路径 | RuoYi 风格 `/system/brand` | `/api/v1/<资源>`，幂等键 + trace_id | 概要设计 §7.1 |
| 权限 | 权限标识 + 菜单表 | 权限标识 + 运行时能力清单 | 前端按 `capabilities` 渲染，后端二次校验 |
| 日志 | SLF4J 注解 | structlog JSON 字段规范 | 需要 trace 贯穿工作流与执行 |
| 部署手册 | Nacos + Maven | `.env` + Alembic + uvicorn | 技术栈不同，验证清单按本模块重写 |
