# 生产级 ETL-Agent 数据集成平台 身份与租户 数据对象设计

本文档描述 M01 的实体关系、不可变边界，以及跨模块共享的上下文对象。表字段与 DDL 以《后端SPEC.md》第 4 章为准，本文不重复，只说明「实体之间是什么关系、哪些能改、谁在消费」。

## 1. 实体清单

| 实体 | 表 | 角色 | 可变性 |
| --- | --- | --- | --- |
| 租户 | `iam_tenant` | 隔离边界 | 可变配置（`code` 不可改） |
| 用户 | `iam_user` | 平台主体 | 可变配置 |
| 项目 | `iam_project` | 隔离边界 | 可变配置（`ARCHIVED` 为终态） |
| 角色 | `iam_role` | 系统配置 | 运行期只读 |
| 成员 | `iam_member` | 关系 | 只置 `REMOVED`，不删除 |
| 成员角色 | `iam_member_role` | 关系 | 只追加与置失效 |
| 会话 | `iam_auth_session` | 运行态 | 只置 `revoked_at`，可按过期归档 |
| 凭据 | `iam_user_credential` | 附属 | 可变（仅本地认证启用时存在） |

## 2. 实体关系

```
iam_tenant 1 ──── n iam_project
    │                   │
    │                   ├──── n iam_member ──── 1 iam_user ──── 1 iam_user_credential
    │                   │            │
    │                   │            └──── n iam_member_role ──── 1 iam_role
    │                   │
    │                   └──── n iam_auth_session（按 user 归属，不按 project）
    │
    └──── n iam_member（冗余 tenant_id 用于隔离校验）
```

说明两点：

1. **会话不绑定项目**。`iam_auth_session` 只关联 `user_id`，当前项目是会话上的一个字段（`current_project_id`，见迁移 `0003_iam_session_project`）。这样切项目不需要重建会话。
2. **成员是用户与项目的连接表**，同时冗余 `tenant_id`。冗余的目的不是查询方便，而是让「同一租户」这条约束可以用复合条件校验，避免仅凭 `project_id` 反查时漏掉租户不一致。

## 3. 不可变边界

| 实体 | 允许的操作 | 禁止 |
| --- | --- | --- |
| `iam_tenant` | 改名、改状态 | 改 `code`、物理删除 |
| `iam_project` | 改名、改状态（`ARCHIVED` 终态） | 改 `code`、改 `tenant_id`、物理删除 |
| `iam_user` | 改名、改状态 | 改 `external_subject`（换认证主体等于换人） |
| `iam_member` | `ACTIVE` ↔ `REMOVED` | 物理删除、改 `user_id` / `project_id` |
| `iam_member_role` | 新增、置 `valid_to` | 删除、改 `role_id` / `member_id` / `valid_from` |
| `iam_auth_session` | 置 `revoked_at`、更新 `last_seen_at` | 改 `user_id`、改 `token_hash` |
| `iam_role` | 无（种子数据） | 运行期增删改 |

为什么角色分配不能「改」：审批事实里记录的是「谁在什么角色下批的」。如果允许把一条历史记录的角色改成另一个，历史审批的责任主体就被改写了。因此只允许把旧记录失效、再追加新记录。

## 4. 跨模块共享对象

### 4.1 `RequestContext`

本模块最重要的输出不是接口，而是这个对象。所有下游模块的隔离与操作主体都从它取。

| 字段 | 类型 | 来源 | 用途 |
| --- | --- | --- | --- |
| `trace_id` | `str` | 请求头 `X-Trace-Id` 或入口生成 | 贯穿工作流、授权、执行、审计 |
| `tenant_id` | `UUID` | 用户所属租户 | 隔离键 |
| `project_id` | `UUID \| None` | 会话当前项目 | 隔离键；未选项目时为空 |
| `user_id` | `UUID` | 会话 | 操作主体 |
| `roles` | `list[str]` | 当前项目有效角色 | 供 Harness 判定审批槽位 |
| `approval_slots` | `list[str]` | 由角色推导 | `DATA` / `SECURITY` |
| `capabilities` | `list[str]` | 角色→能力映射 | 接口鉴权与前端渲染 |

约束：

- `RequestContext` **只读**，下游不得修改后继续传递。
- `tenant_id` 与 `project_id` 必须来自会话，**不接受请求体传入**。任何接口出现从 body 读 `tenant_id` 的写法都是越权漏洞。
- `capabilities` 由后端计算，前端传上来的一律忽略。

### 4.2 审计事件

| 事件 | 触发点 | 载荷要点 |
| --- | --- | --- |
| `IAM_PROJECT_CREATED` | 项目创建成功 | `project_id`、`code`、`operator_id` |
| `IAM_MEMBER_INVITED` | 成员加入 | `member_id`、`user_id`、`role_codes` |
| `IAM_MEMBER_REMOVED` | 成员移除 | `member_id`、`operator_id` |
| `IAM_ROLE_ASSIGNED` | 角色分配 | `member_id`、`role_code`、`reason`、`assignment_id` |
| `IAM_ROLE_REVOKED` | 角色失效 | `member_id`、`assignment_id`、`operator_id` |
| `IAM_LOGIN_SUCCEEDED` | 登录成功 | `user_id`、`session_id`、`ip` |
| `IAM_LOGIN_FAILED` | 登录失败 | `subject_hash`、`ip`、`code` |

事件异步投递给 M11 审计，投递失败不回滚主流程——但必须在 `harness_outbox_event` 留下待补投记录（本模块只写 outbox，消费由 M11 负责）。

### 4.3 下游消费清单

| 消费方 | 取用什么 | 说明 |
| --- | --- | --- |
| M02 凭据与连接 | `project_id`、`user_id` | 连接归属与责任人 |
| M03–M10 | `RequestContext` | 隔离与操作主体 |
| M07 Harness | `roles`、`approval_slots` | 判定审批槽位是否满足；**不重复实现角色判断** |
| M11 审计 | 六类 `IAM_*` 事件 | 证据链输入 |
| 前端 | `capabilities`、`project`、`roles` | 入口渲染 |

## 5. 状态与流转

### 5.1 项目状态

```
ACTIVE ──▶ SUSPENDED ──▶ ACTIVE
   │
   └──▶ ARCHIVED（终态，不可回退）
```

`SUSPENDED` 期间成员与角色不变，但除 `GET /auth/session` 外的项目内写接口返回 `IAM_PROJECT_SUSPENDED`。`ARCHIVED` 后项目只读，且不出现在 `GET /projects` 默认列表（需显式 `status=ARCHIVED` 查询）。

### 5.2 成员状态

```
ACTIVE ──▶ REMOVED
```

单向。移除时同时把所有角色置 `valid_to`；再邀请同一用户会复用原 `iam_member` 记录（`uq_iam_member` 保证唯一），把 `status` 改回 `ACTIVE`，不新建成员。

### 5.3 角色分配状态

```
有效（valid_to IS NULL）──▶ 失效（valid_to 非空）
```

同一成员对同一角色，任意时刻最多一条有效记录，由部分唯一索引 `uq_iam_member_active_role` 保证。失效后可以再次分配，产生新记录。

### 5.4 会话状态

```
ISSUED ──▶ EXPIRED（expires_at 到期）
   └────▶ REVOKED（主动注销）
```

两种终态都不可恢复。`EXPIRED` 由查询时按 `expires_at < now()` 判定，不依赖定时清理任务；清理任务只负责归档。

## 6. 与其他模块的边界

| 事项 | 归属 | 说明 |
| --- | --- | --- |
| 角色定义与分配 | M01 | 本模块 |
| 审批槽位是否满足、是否自批 | M07 | 本模块只给角色事实 |
| 双槽是否必须不同人 | M07 | 取决于 TBD-01，不由 M01 决定 |
| 权限矩阵的策略化调整 | M12 | 本模块的映射表是基线，策略版本在 M12 |
| 用户创建 | 平台管理员 / 目录同步 | 邀请接口**不自动建用户**，避免伪造主体 |
| 企业 SSO | 待定（TBD-03） | 未冻结前只保留 `OIDC` 适配位 |
