# 生产级 ETL-Agent 数据集成平台 身份与租户 — 后端开发部署手册

本手册用于把 M01 身份与租户模块在本地跑起来并联调通过。命令均以项目根目录为工作目录。

---

## 1. 前置条件

| 组件 | 版本 | 校验命令 | 期望 |
| --- | --- | --- | --- |
| Python | 3.11+ | `python --version` | `Python 3.11.x` 及以上 |
| PostgreSQL | 16+ | `psql --version` | `psql (PostgreSQL) 16.x` |
| Redis | 7+ | `redis-cli --version` | `redis-cli 7.x` |
| Node.js | 20+ | `node --version` | `v20.x` |
| pnpm | 9+ | `pnpm --version` | `9.x` |
| Vault | 1.15+ | `vault version` | `Vault v1.15.x`（本模块暂不强制依赖，见 §3.4） |

本模块只依赖 PostgreSQL 与 Redis；Vault、SeaTunnel 可以不起，不影响登录与成员管理联调。

## 2. 数据库配置

### 2.1 创建数据库

```bash
psql -U postgres -c "CREATE DATABASE etlagent OWNER etlagent;"
psql -U postgres -c "CREATE USER etlagent WITH PASSWORD 'etlagent_dev';"
psql -U postgres -c "GRANT ALL PRIVILEGES ON DATABASE etlagent TO etlagent;"
```

### 2.2 执行建表

本模块的建表语句以《后端SPEC.md》第 4 章为准。两种方式任选其一：

**方式一：Alembic 迁移（推荐）**

```bash
cd apps/api
alembic upgrade head
```

**方式二：手工执行 DDL**

```bash
psql -U etlagent -d etlagent -f migrations/sql/0001_iam.sql
```

手工执行后必须补写 Alembic 版本记录，否则 `alembic upgrade head` 会重复建表：

```bash
cd apps/api && alembic stamp 0001_iam
```

### 2.3 验证建表结果

```bash
psql -U etlagent -d etlagent -c "\dt iam_*"
```

期望输出七张表：

```
 iam_auth_session
 iam_member
 iam_member_role
 iam_project
 iam_role
 iam_tenant
 iam_user
```

校验唯一索引是否生效：

```bash
psql -U etlagent -d etlagent -c "\di uq_iam_member_active_role"
```

### 2.4 初始化角色基线

```bash
psql -U etlagent -d etlagent -f migrations/seed/iam_role.sql
```

```sql
INSERT INTO iam_role (id, code, name, scope, is_business_approval_role) VALUES
  (gen_random_uuid(), 'MAKER',            '需求提出者',       'PROJECT', false),
  (gen_random_uuid(), 'CHECKER_DATA',     '审批人·业务维度',  'PROJECT', true),
  (gen_random_uuid(), 'CHECKER_SECURITY', '审批人·安全维度',  'PROJECT', true),
  (gen_random_uuid(), 'OPERATOR',         '操作员',           'PROJECT', false),
  (gen_random_uuid(), 'AUDITOR',          '审计',             'PROJECT', false),
  (gen_random_uuid(), 'PROJECT_ADMIN',    '项目管理员',       'PROJECT', false)
ON CONFLICT (code) DO NOTHING;
```

角色表是系统配置，`ON CONFLICT DO NOTHING` 保证可重复执行。

## 3. 环境变量与配置

### 3.1 `.env` 示例

```ini
APP_ENV=dev
API_PREFIX=/api/v1

DATABASE_URL=postgresql+asyncpg://etlagent:etlagent_dev@localhost:5432/etlagent
REDIS_URL=redis://localhost:6379/0

SESSION_TTL_HOURS=8
SESSION_COOKIE_NAME=etl_session
SESSION_COOKIE_SECURE=false
SESSION_COOKIE_SAMESITE=lax

AUTH_PROVIDER_LOCAL_ENABLED=true
AUTH_PROVIDER_OIDC_ENABLED=false
AUTH_MAX_FAILED_ATTEMPTS=5
AUTH_LOCK_MINUTES=15

LOG_LEVEL=DEBUG
LOG_FORMAT=json
```

### 3.2 关键配置说明

| 变量 | 说明 | 生产要求 |
| --- | --- | --- |
| `SESSION_COOKIE_SECURE` | 是否只在 HTTPS 下发 Cookie | 生产必须 `true` |
| `SESSION_TTL_HOURS` | 会话有效期 | 与 SPEC 的 8 小时一致，改动需同步 SPEC |
| `AUTH_PROVIDER_OIDC_ENABLED` | 企业 SSO 开关 | TBD-03 未冻结前保持 `false` |
| `LOG_FORMAT` | `json` 或 `console` | 生产必须 `json`，否则日志采集解析失败 |

### 3.3 Redis 用途

| 键 | 用途 | TTL |
| --- | --- | --- |
| `session:blacklist:<token_hash>` | 注销后的令牌黑名单 | 取会话剩余有效期 |
| `session:touch:<session_id>` | `last_seen_at` 写入去重 | 60 秒 |

Redis 不是权威存储：清空 Redis 只导致已注销令牌在剩余有效期内仍可用（可接受）与 `last_seen_at` 频率上升，不影响认证结果。

### 3.4 Vault

本模块不读取任何 Secret，`VAULT_ADDR` 可以留空。若启动时报 Vault 连接失败，检查 `modules/asset` 是否被误加载。

## 4. 后端构建与启动

### 4.1 安装依赖

```bash
cd apps/api
python -m venv .venv
source .venv/Scripts/activate      # Windows Git Bash
pip install -e ".[dev]"
```

### 4.2 启动 API

```bash
uvicorn app.main:app --reload --port 8000
```

启动成功标志：

```
INFO  application startup complete
INFO  Uvicorn running on http://127.0.0.1:8000
```

### 4.3 验证服务

```bash
curl -s http://localhost:8000/api/v1/auth/session | jq
```

未登录期望返回：

```json
{"code": "AUTH_UNAUTHENTICATED", "message": "未登录或会话已失效", "data": null,
 "trace_id": "...", "retriable": false}
```

接口文档：`http://localhost:8000/docs`。

### 4.4 种子账号

```bash

  --user local:zhanglan --role MAKER --password 'CorrectHorseBattery'
```

脚本行为：建租户 → 建项目 → 建用户与凭据 → 建成员 → 分配角色。重复执行只会补齐缺失项。

## 5. 接口验证清单

按顺序执行，全部通过说明本模块可用。

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | `GET /api/v1/auth/session` 未登录 | 401 `AUTH_UNAUTHENTICATED` |
| 2 | `POST /api/v1/auth/login` 正确凭据 | 200，返回 `session_token` 与 `projects` |
| 3 | 同上，错误密码 | 401 `AUTH_INVALID_CREDENTIALS` |
| 4 | 连续 5 次错误密码 | 第 6 次返回 423 `AUTH_ACCOUNT_LOCKED` |
| 5 | 带 Cookie 调 `GET /auth/session` | 200，`capabilities` 非空 |
| 6 | `POST /auth/logout` 后再次 `GET /auth/session` | 401 `AUTH_SESSION_REVOKED` |
| 7 | `GET /projects` | 只返回当前用户为成员的项目 |
| 8 | 重复 `code` 创建项目 | 409 `IAM_PROJECT_CODE_CONFLICT` |
| 9 | `GET /projects/{id}/members` | 返回成员与角色，`email_masked` 非明文 |
| 10 | 邀请不存在的 `external_subject` | 404 `IAM_USER_NOT_FOUND` |
| 11 | 重复分配同一角色 | 409 `IAM_ROLE_ALREADY_ASSIGNED` |
| 12 | 用 MAKER 账号调 `POST /projects` | 403 `AUTH_FORBIDDEN` |

### 5.1 数据库断言

登录一次后执行：

```bash
psql -U etlagent -d etlagent -c \
  "select length(token_hash), revoked_at, expires_at from iam_auth_session order by issued_at desc limit 1;"
```

期望 `length = 64`（SHA256 十六进制），且全库搜索不到明文令牌：

```bash
psql -U etlagent -d etlagent -c "select count(*) from iam_auth_session where length(token_hash) <> 64;"
```

期望 `0`。

## 6. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `relation "iam_tenant" does not exist` | 未执行迁移 | `alembic upgrade head` |
| `alembic upgrade head` 报表已存在 | 手工建过表但未 stamp | `alembic stamp 0001_iam` |
| 登录成功但刷新页面掉登录 | Cookie `Secure=true` 但走 http | 开发环境把 `SESSION_COOKIE_SECURE` 设为 `false` |
| 所有接口 401 | 前端未带 Cookie（跨域未开 `credentials`） | 前端 `withCredentials: true`，后端 CORS 需 `allow_credentials=True` 且 `allow_origins` 不能用 `*` |
| 登录报 `asyncpg.InvalidPasswordError` | 连接串密码错 | 核对 `.env` 与建库时的密码 |
| 连续失败未锁定 | Redis 未启动，计数未生效 | 启动 Redis 或检查 `REDIS_URL` |
| `IAM_SCOPE_MISMATCH` | 传入的 `project_id` 与会话项目不一致 | 前端切换项目后重新拉 `session` |
| 分配角色后能力未变 | 前端缓存了旧 `session` | `switchProject` 或刷新后重拉 `GET /auth/session` |
| 日志无 `trace_id` | 中间件未注册 | 检查 `main.py` 是否挂载 `TraceIdMiddleware` |
